2. Arquitectura de la API

El backend está construido bajo un enfoque moderno y seguro:

  • Framework: Spring Boot 3.3.x con Java 17.
  • API Gateway: Spring for GraphQL (Reemplazando los controladores REST tradicionales, centralizando en /graphql).
  • Autenticación: JSON Web Tokens (JJWT 0.12) mediante Bearer Tokens en headers.
  • Base de Datos: PostgreSQL 16 manejado mediante Spring Data JPA.
  • Migraciones: Flyway para control de versiones de esquema y carga de datos inicial.
  • Seguridad: Seguridad a nivel de método con @PreAuthorize basada en la jerarquía de roles (RBAC).

4. Flujo de Autenticación

Toda petición a GraphQL (excepto login) requiere autenticación JWT.

1

Realizar Login (REST)

Endpoint: POST /api/v1/auth/login

{
    "username": "admin",
    "password": "password123"
}
2

Capturar Token

La respuesta devolverá el token de acceso:

{
    "accessToken": "eyJhbGciOiJIUz...",
    "refreshToken": "eyJhbGciOiJIUz...",
    "expiresIn": 86400000,
    "username": "admin",
    "roles": ["ROLE_ADMIN"]
}
3

Configurar Authorization Header en Postman

Ve a la pestaña Authorization en tus peticiones de GraphQL, selecciona el tipo Bearer Token y pega el accessToken (o usa la variable {{token}}).

5. Roles del Sistema

Rol Identificador Interno Permisos Principales
Administrador ROLE_ADMIN Acceso total. Crear usuarios, asignar roles, desactivar empleados, modificar configuraciones del sistema (IoT).
Recursos Humanos ROLE_RRHH Gestión completa de empleados, cargos, departamentos, generación de planillas y aprobación global de ausencias.

6. Queries (Consultas)

Consultas de lectura (equivalente a GET en REST). Utiliza el método POST /graphql.

usuarios

Lista todos los usuarios del sistema.

Permisos: ROLE_ADMIN

query {
  usuarios {
    id
    username
    activo
    roles {
      rol { nombre }
    }
  }
}

empleados

Lista empleados con paginación y filtros opcionales.

Permisos: Autenticado

Variables JSON:

{ "page": 0, "size": 10, "estado": "ACTIVO", "departamentoId": "1" }

GraphQL:

query GetEmpleados($page: Int, $size: Int, $estado: EstadoEmpleado, $departamentoId: ID) {
  empleados(page: $page, size: $size, estado: $estado, departamentoId: $departamentoId) {
    content {
      id
      nombreCompleto
      estado
      cargo { nombre }
    }
    pageInfo { totalElements totalPages }
  }
}

departamentos y cargos

Obtiene catálogos del sistema.

Permisos: Autenticado

query {
  departamentos { id nombre gerente { nombreCompleto } }
  cargos { id nombre salarioPorHora }
}

registrosAsistencia

Obtiene el historial de asistencia biométrica.

Permisos: Autenticado

Variables JSON:

{ "empleadoId": "1", "page": 0, "size": 20 }

GraphQL:

query GetAsistencia($empleadoId: ID, $page: Int, $size: Int) {
  registrosAsistencia(empleadoId: $empleadoId, page: $page, size: $size) {
    content {
      id
      empleado { nombreCompleto }
      horaEntrada
      horaSalida
      estado
    }
  }
}

solicitudesAusencia

Consulta solicitudes de permisos/vacaciones.

Permisos: Autenticado

7. Mutations (Modificaciones)

Operaciones de escritura (equivalente a POST, PUT, DELETE en REST).

crearEmpleado

Registra un nuevo empleado en la base de datos.

Permisos: ADMIN RRHH

Variables JSON:

{
  "input": {
    "nombre": "Juan",
    "apellido": "Pérez",
    "fechaContratacion": "2026-06-01",
    "departamentoId": "1",
    "cargoId": "3",
    "horaEntrada": "08:00:00",
    "horaSalida": "17:00:00",
    "telefono": "70012345",
    "carnetIdentidad": "1234567"
  }
}

GraphQL:

mutation Crear($input: EmpleadoInput!) {
  crearEmpleado(input: $input) {
    id
    nombreCompleto
    estado
  }
}

enrolarRostro (IoT)

Registra el hash biométrico del rostro de un empleado capturado por el sensor de portería.

Permisos: ADMIN RRHH

mutation {
  enrolarRostro(empleadoId: "1", codigoFacial: "FACE_HASH_ABC123") {
    id
    fechaRegistro
  }
}

registrarEntrada / registrarSalida (IoT)

Simula el evento del sensor biométrico capturando un rostro conocido.

Permisos: Ninguno (Público, el IoT device llama este endpoint con su propio mecanismo).

Variables JSON:

{
  "input": {
    "codigoFacial": "FACE_HASH_ABC123",
    "ubicacionGps": "10.4806,-66.9036"
  }
}

GraphQL:

mutation Entrada($input: RegistroAsistenciaInput!) {
  registrarEntrada(input: $input) {
    id
    horaEntrada
    estado
  }
}

El empleado solicita vacaciones, permiso médico, etc.

Permisos: Autenticado

Aprobación de la solicitud por parte del gerente/supervisor o RRHH.

8. Escenarios Empresariales: Workflow Completo de RRHH

Guía paso a paso para probar un flujo operativo real desde cero:

  1. Autenticación como Admin: Realiza un POST /api/v1/auth/login con admin / password123. Configura el token resultante en tus headers.
  2. Verificar Departamentos y Cargos: Ejecuta la query departamentos y cargos para obtener los IDs disponibles (ej. Departamento 1, Cargo 3).
  3. Alta de Nuevo Empleado: Usa la mutation crearEmpleado pasando el input requerido. Copia el id devuelto.
  4. Enrolamiento IoT: Llama a la mutation enrolarRostro utilizando el ID del empleado recién creado y un hash ficticio (ej. "NUEVO_ROSTRO_XYZ").
  5. Simular Llegada al Trabajo: (Quita el header Authorization si lo deseas). Llama a registrarEntrada con el código facial "NUEVO_ROSTRO_XYZ".
  6. Simular Salida del Trabajo: Llama a registrarSalida con el código facial "NUEVO_ROSTRO_XYZ" al final del turno.
  7. Cierre de Mes: Restaura tu token de Admin. Llama a generarPreplanilla para ese empleado pasando el periodo "2026-06".

10. Manejo de Errores (Exceptions)

El API maneja los errores mediante el GlobalExceptionHandler, retornando un formato estándar. Errores GraphQL retornan en la propiedad errors de la respuesta.

Código / Tipo Motivo Ejemplo en Proyecto
401 Unauthorized Falta JWT, JWT expirado, credenciales inválidas. Fallo en endpoint /login por mala contraseña.
403 Forbidden El rol del usuario no tiene permisos para el endpoint. Un Empleado intenta llamar a crearEmpleado() (que requiere RRHH o ADMIN).
404 Not Found Entidad solicitada no existe. Query empleado(id: 999) y lanza ResourceNotFoundException.
400 / 422 Bad Request Validaciones de negocio fallidas o integridad. Tratar de aprobarSolicitudAusencia de una solicitud que ya está rechazada. Lanza BusinessRuleException.

12. Guía Rápida para QA (Checklist)

Sigue esta lista para comprobar la robustez y seguridad del API:

  • Verificar que cualquier petición a GraphQL sin el token Bearer retorna Error 401.
  • Loguearse con admin (clave password123) y comprobar que el Token devuelto es un JWT válido.
  • Ejecutar una Query básica como { departamentos { id nombre } } y validar estado HTTP 200.
  • Autenticarse como empleado básico (ej. d.lozano) y tratar de ejecutar crearEmpleado. Validar que lanza Excepción de Acceso Denegado (Forbidden).
  • Probar registrar entrada (registrarEntrada) con un hash que NO existe. Validar que retorna "Rostro no reconocido".
  • Loguearse como RRHH (ej. v.mendoza) y aprobar una solicitud PENDIENTE (id 9 o superior según datos de prueba).
