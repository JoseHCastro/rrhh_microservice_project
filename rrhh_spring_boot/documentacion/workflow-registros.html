⚙️ Secuencia Lógica de Inserción (Respetando Foreign Keys)

Para evitar errores de violación de integridad referencial, los datos fueron insertados en el siguiente orden estricto:

  1. Cargos y Departamentos (Base): Se crearon 14 cargos distintos con diferentes salarios y los 4 departamentos principales (con gerente_id = NULL temporalmente).
  2. Empleados: Se insertaron los 37 empleados, asignando su cargo_id, departamento_id y supervisor_id (permitiendo jerarquías reales).
  3. Actualización de Gerentes: Se hizo un UPDATE en la tabla de departamentos para asignar el gerente_id correspondiente.
  4. Usuarios y Roles: Se crearon cuentas de usuario para los 37 empleados (más el admin existente), con hash BCrypt válido (password123). Se asignaron los roles ROLE_RRHH, ROLE_SUPERVISOR y ROLE_EMPLEADO según el departamento y cargo.
  5. Biometría e IoT: Se generaron 37 hashes faciales simulados para el enrolamiento en portería.
  6. Asistencia Diaria: Se generó una muestra de 60 marcaciones (con latitud/longitud real de Caracas) para 6 empleados clave durante Abril y Mayo, simulando llegadas a tiempo, retrasos, y omisiones de marcado.
  7. Solicitudes de Ausencia: 30 solicitudes (vacaciones, permisos médicos) en diferentes estados (APROBADA, RECHAZADA, PENDIENTE) vinculadas al aprobador_id.
  8. Preplanillas (AWS S3): 109 registros simulando el cierre de nómina de Marzo, Abril y Mayo, con rutas lógicas preplanillas/2026-XX/emp-YY.pdf.
  9. Tokens FCM: 37 tokens generados algorítmicamente para simular dispositivos iOS y Android registrados para notificaciones push.

🗂️ Simulación Híbrida DynamoDB (Auditoría)

Los datos transaccionales se encuentran en PostgreSQL. Sin embargo, para representar el escenario completo, la arquitectura incluye Amazon DynamoDB para la tabla BitacoraAuditoria.

Por qué: Para soportar operaciones de alta escritura (append-only) cuando los usuarios acceden al sistema o visualizan preplanillas, desacoplando la carga transaccional de PostgreSQL.

Nota: Los registros de DynamoDB no están en el script SQL, ya que deben insertarse a través del SDK de AWS en la aplicación.
